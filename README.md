# Spatial Catch Allocation MSE

This repository contains the code and supporting materials for the management strategy evaluation described in:

**Can empirical catch allocation strategies based on single-region stock assessments provide adequate advice for managing spatially structured fish populations?**

The study evaluates whether stock-level catch advice generated by a single-region assessment can be distributed among regions and fleets using empirical catch-allocation strategies while maintaining acceptable system-level and regional management performance.

## Overview

Many fisheries are assessed at a broader spatial scale than the scale at which catch limits are implemented. When spatially explicit stock assessments are unavailable or impractical, managers may allocate stock-level catch advice among regions using historical catches, survey indices, equal allocation, or combinations of these information sources.

Using a closed-loop management strategy evaluation conditioned on western Atlantic black sea bass (*Centropristis striata*), this study compares alternative empirical catch-allocation strategies across operating-model scenarios that vary in:

* population structure;
* movement directionality;
* movement magnitude;
* temporal and age-dependent movement;
* regional recruitment dynamics; and
* density-dependent recruitment.

Management performance is evaluated at both system and regional scales using catch, spawning stock biomass, interannual variability, overfishing risk, depletion risk, and multi-metric performance scores.

## Catch-allocation strategies

The repository includes simulations and analyses for five catch-allocation strategies:

1. **Equal**
   Allocates total catch advice equally among all region–fleet combinations.

2. **Gear-Equal**
   Allocates catch between commercial and recreational fleets according to historical fleet shares and then divides each fleet allocation equally between regions.

3. **Fleet-Catch**
   Allocates catch according to historical catch shares for each region–fleet combination.

4. **Index-Equal**
   Allocates catch among regions using regional survey-index information and then divides each regional allocation equally between fleets.

5. **Index-Gear**
   Allocates catch among regions using survey-index information and then allocates catch between fleets using historical fleet catch shares.

## Workflow

The general analytical workflow is:

1. Configure the spatial operating-model scenarios.
2. Simulate spatial population, fishery, survey, movement, and recruitment dynamics.
3. Aggregate regional pseudo-data for use in a single-region estimation model.
4. Fit the assessment model and calculate biological reference points.
5. Generate stock-level catch advice using the harvest control rule.
6. Allocate catch advice among regions and fleets using each empirical allocation strategy.
7. Apply the allocated catches in the operating model.
8. Repeat the assessment-management feedback cycle over the projection period.
9. Calculate system-level and regional performance metrics.
10. Generate manuscript figures and tables.

## Operating-model scenarios

Scenario abbreviations describe population structure, movement, and recruitment assumptions:

* `N`: natal-homing population structure
* `M`: metapopulation structure
* `B`: bidirectional movement
* `U`: unidirectional movement
* `L`: low movement
* `H`: high movement
* `I`: interannual variation in movement
* `O`: ontogenetic movement
* `D`: declining recruitment in population component 1
* `BH`: Beverton–Holt density-dependent recruitment

For example:

* `NBL`: natal homing, bidirectional low movement
* `MUH`: metapopulation, unidirectional high movement
* `NBLD`: natal homing, bidirectional low movement, declining recruitment
* `NULD`: natal homing, unidirectional low movement, declining recruitment

The main scripts should be run in the following order:

```text

02_configure_operating_models.R
03_run_mse.R
04_calculate_performance_metrics.R
05_summarize_results.R
06_create_figures.R
07_create_tables.R
```

Large simulation outputs may not be stored directly in the GitHub repository. When applicable, archived outputs or instructions for regenerating them will be provided through an external research-data repository.
